  1. The app asks the cache for key c.
  2. The cache looks c up.
  3. Hit: c is in the cache.
  4. c moves to the most recent slot. The database is never touched.
  5. The value returns to the app.

Why cache

A cache keeps copies of hot data in fast memory so most reads never reach the database.

The cost is staleness: a cached value can be out of date until it expires or is replaced.

Strategy Writes go to Good for
Cache-aside Database, app fills cache Read-heavy data
Write-through Cache and database Fresh reads

LRU

Evicts the key not used for the longest time. Simple, good default.

LFU

Evicts the least frequently used key. Better for stable hot sets.

Pitfall: stale reads

After a write, the cache can still serve the old value. Decide how you expire or invalidate it.
